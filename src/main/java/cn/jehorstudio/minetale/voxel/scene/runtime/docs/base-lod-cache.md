# 基础 LOD 缓存

Core 的 Raw 空间页和曲面来源只包含 `needs_subdivision` 组。场景首次加载时，客户端为该组生成每方块 0.5 个体素的基础模型；颜色、自发光、PBR 和法线也使用 0.5 采样精度，体素边长为 2 方块。固定 Mesh 的 `raw/fixed/` 数据原样复制到缓存，几何及材质生命周期由 [SceneFixed](fixed-geometry.md) 管理。

## 生成与显示

`SceneBase` 按 32 方块空间页执行与近场相同的保守体素化和 Greedy 合并。来源包围盒扩展一格 Halo 后确定页集合，覆盖负坐标和页边缘。各页材质块打包到一张二次幂图集，顶点 UV 与区域中心同步变换。Low 矩形按 012/023 排列，保持原绕序和着色帧，使既有砖裁切和 POM 区域信息继续有效。

`SceneClient` 管理加载令牌和世界归属，`SceneLoader` 在专用场景线程准备资产和基础 LOD。缓存需要生成时，主线程创建隐藏的共享 OpenGL context，工作线程绑定该 context，生成几何、编译材质、执行分批 compute、读取有效通道的两级 mip 并编码 PNG。窗口创建和销毁归主线程；工作线程释放 context 后再销毁窗口。首次生成需要 OpenGL compute、SSBO 和 image load/store。

完整缓存生成后进入既有读取、分帧上传和 Low 绘制路径。基础图集、两级 mip 和顶点全部上传完成后显示场景。稳定帧使用单个 Low 顶点缓冲和单图集，可见页范围变化时更新合并索引，常驻 Low 一次提交。借用 Low 材质的 High 边界截面使用各自的顶点缓冲。几何和材质生成发生在首次加载阶段。

## 持久化与失效

缓存位于游戏目录 `cache/minetale/core-lod/`，由三个域组成：

- `geometry-<SHA-256>.bin`：来源几何及显式几何版本，保存可复用的几何快照。
- `color-<SHA-256>.bin`：几何键、来源颜色／自发光及相关 shader 依赖，保存颜色和 emission。
- `<SHA-256>.mtscene`：来源包、展开 shader、光影出口和完整资产版本，保存可直接装载的结果。

这些键使用显式版本，不依赖 Java 字节码。改变生成语义或缓存布局时必须递增对应键中的版本。重启、退出世界、重新摆放以及相同资源的重载复用已完成缓存；仅 PBR 出口变化时可以复用几何和颜色。

生成结果先写入同目录临时文件，完成后替换目标文件；支持的平台使用原子移动。生成失败或取消时清理临时文件。缓存读取验证失败时重新生成。生成令牌与场景加载生命周期一致，发布资格限定为当前加载结果。GPU 和文件句柄随当前场景释放，本地完成缓存跨进程保存。

缓存声明 `version="1.1"`、`low_encoding="float32"`、`texture_encoding="png"`，保存浮点页、PNG 和显式 mip；GPU 输出的颜色、独立自发光、有效 PBR／法线及 mip 保存到缓存；无光影出口裁剪未消费的 PBR／法线。Raw 页按新空间页 ID 对应复制，保留 Raw 调试入口。

## 索引与截面

缓存 Low 的合并、坐标和顶点偏移由本次生成确定。加载时重建页 BVH、砖目录和最高精度来源关联，稳定视点复用已有查询缓存。`SceneSeams` 持有该 Low 的紧凑面信息，在细节砖请求时生成对应截面。新模型接管依据本次缓存的索引和截面；原导入 LOD 的占用、截面和连通图保持在原模型范围。

生成 Low 的截面由 `SceneSeamCache` 复用，键包含实际 Low 面的位置、UV、绕序相关信息、页尺寸和砖尺寸。High 精度切换、材质重烘焙、位置平移和 High 驻留回收不会使接缝失效。内存缓存按最近使用顺序淘汰，数据预算为 16 MiB，最多 16,384 个条目；所有生成与文件 IO 都在场景工作线程执行。

游戏内“体素 → 大场景”管理该接缝磁盘缓存，配置文件为 `minetale-voxel-client.toml`：

```toml
[scene]
seam_disk_cache = false
seam_cache_path = ""
```

磁盘缓存默认关闭，关闭时保持内存复用。路径留空时使用游戏目录下的 `cache/minetale/core-seams/`；非空时使用指定目录，相对路径以游戏目录为基准。配置在下次加载场景时应用。此开关只控制新增接缝缓存，基础 LOD 的几何、颜色和完整资产缓存使用前述独立规则。

启用后，各砖保存在 `v1-<SHA-256>/<x>_<y>_<z>.bin`。Low 面或 UV 变化自动切换目录；修改 `SceneSeams.lowCaps` 的生成规则或文件编码时必须递增接缝目录版本。条目包含长度、面数、有限顶点及 CRC 校验，损坏时重新生成；写入通过临时文件替换，文件系统支持时使用原子移动。目录不可写时当前场景使用内存缓存。首次计算与写入有额外成本，磁盘命中用于跨重启复用。

四项精度同时为 0.5 时显示常驻基础 LOD。几何 0.5 配合其他材质精度时，使用 8 方块近场砖独立生成。其他导入资产的四项 0.5 使用原始 LOD。

## 成本边界

分发体积减少的是预烘焙 Low、贴图及依赖源 Low 的索引。首次加载增加全量生成、GPU 材质求值、编码和写盘，并在期间占用额外 CPU 内存和 GPU 纹理。缓存命中包含几何与图片解码、索引重建和上传成本。

稳定绘制沿用既有路径；真实体素化会改变矩形数量、裁切后顶点量和材质外观。性能比较分别记录首次生成、缓存命中、常驻资源、相同视点的提交量和 GPU 时间。独立 OpenGL 验证覆盖材质和绘制路径的组成部分，Minecraft/Iris 整帧耗时在实际游戏环境中验证。
